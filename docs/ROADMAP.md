## 范围与使用规则

本轮将现有原型正式化：React + Vite 前端、本地单用户 Node 服务、SQLite 持久化、三个 Pi Agent 场景、真实项目文件和本机终端。

不包含多用户、容器、第三方插件、自动部署，以及尚未单独确认的补救任务系统、最终作品验收等产品增强。

- 任务编号可作为后续开发和评审的引用，不代表已经创建外部工单。
- 勾选任务前必须同时满足交付物和验收标准；实现完成但未验证时保持未勾选，并注明阻塞原因。
- 验证时记录执行的检查、结果和限制。模拟模型测试与真实 Provider 测试分开记录。
- 技术验证使用独立临时数据目录，不操作已有学习数据；密钥、数据库和用户项目不纳入 Git。
- 保留 `prototype` 分支及 `.worktrees/prototype` 作为参考。每个里程碑按下述纪律建立独立实施分支，不覆盖原型。
- 只有影响已确认架构、权限或产品范围的变化才回到方案讨论；不为普通实现细节新增审批环节。

## 实施纪律：按里程碑建分支，按节点提交

1. **每个里程碑开始前先创建新分支。**从已包含所需前置成果的 `main` 创建该里程碑的独立分支，再开始修改代码；不得直接在 `main` 上实施，也不得沿用上一个里程碑的分支。前置成果尚未合入 `main` 时，先确认集成安排，不擅自合并或换用其他基线。
2. **每个任务节点完成后提交一次，再进入下一节点。**这里的节点指下文每个带编号的任务。完成该节点的实现、相关验证和 ROADMAP 状态更新后，将对应代码、测试及文档作为一次完整的本地提交；不得把多个已完成节点攒到里程碑结束才提交，也不得夹带无关改动。未达到验收标准时不得以“完成节点”为由提交或勾选完成。
3. **分支名采用语义化的 `<type>/<short-description>`。**类型按实际工作选择 `feat`、`fix`、`refactor`、`build`、`test`、`docs` 或 `chore` 等；描述使用小写英文和连字符，表达实际功能、模块或工程变化。本项目采用这一约定，不以 ROADMAP 编号命名分支。
4. **Commit message 采用 Conventional Commits。**格式为 `<type>(<scope>): <description>`，scope 可省略；scope 使用真实模块名，description 使用简短英文动词短语说明实际改动。需要时在正文解释原因和验证结果，而不是记录推进到了哪个计划节点。
5. **禁止规划编号和脚手架式过程话术进入分支名或 commit message。**不得使用 `M1-implement`、`feat/milestone-2`、`提交了 M2.2`、`chore: complete M1.1`、`update` 或 `finish implementation` 等名称或说明。里程碑和节点编号仅用于 ROADMAP 跟踪，不写入分支名、提交标题或正文。
6. **本地提交不等于远端交付。**节点完成后按本纪律提交，但不自动推送、合并、发布或部署；里程碑结束时明确报告分支、验证结果及尚未执行的交付步骤。
7. **迁移必须复用原组件，逐组件验收。**接入真实数据时替换状态来源和操作实现，保留已有页面与组件树，不另写一套仅外观相似的正式界面。在相同输入下对照未修改的参考版本，检查组件 DOM、样式、图标、文本和交互；另用真实 API 验证正式入口的保存、恢复及失败状态。必要的手动保存、冲突处理和能力提示须明确记录，不得用只通过 `/preview` 或自动更新快照替代正式入口验收。

命名示例应按实际改动选择，不机械套用：

| 用途 | 合适示例 | 不合适示例 |
| --- | --- | --- |
| 本地服务工程分支 | `build/local-web-runtime` | `M1-implement` |
| 前端迁移分支 | `refactor/vite-client` | `feat/milestone-2` |
| 项目文件功能分支 | `feat/local-project-files` | `feat/m3-tasks` |

## 里程碑与依赖

| 里程碑 | 可交付结果 | 主要依赖 | 当前状态 |
| --- | --- | --- | --- |

| M3 持久化与真实文件 | 空间、会话和学习记录可恢复，编辑器读写真正的项目文件 | M1 存储和访问保护、M2 界面 | 已验证，独立分支本地交付，未合并/推送 |
| M4 Agent 场景接入 | 需求、路线、课程使用真实模型，产物经校验和确认 | M3 业务数据、M1 Pi 验证 | 未开始 |
| M5 本机执行 | 真实终端、执行确认与代码测评接通 | M3 项目文件、M4 Agent 和测评任务 | 未开始 |
| M6 整体交付 | 生产模式单服务启动，主流程及恢复场景通过验收 | M1–M5 | 未开始 |

默认按 M1 → M2 → M3 → M4 → M5 → M6 推进。以下依赖不能用模拟结果替代：

1. M4 可以验证出题、结果 schema 和执行结果的接入逻辑，但真实代码测评的完整验收依赖 M5.4。
2. M4 中的 Agent 文件修改和命令执行工具保持不可执行，直到 M5.3 的用户确认机制接通。
3. 缺少模型凭据时，M1.3 的真实 Provider 验证标为阻塞；不妨碍界面和存储工作，但必须在 M4 真实联调前补齐。
4. 文件、Agent 和终端接口必须接入 M1.4 的访问保护后才能对浏览器开放。

## M1：工程骨架与兼容性验证

**目标：**先证明选定技术可以组成一个本地应用，不在这一阶段实现完整教学业务。

### [x] M1.1 建立 workspace 与启动链路

- **交付：**建立 `apps/web`、`apps/server`、`packages/contracts`，配置 TypeScript、Vite、Hono，以及根级开发、构建、检查和启动命令。锁定运行时要求和依赖版本，不预先生成无用途的模块。
- **验收：**开发时一个命令启动前后端；生产构建后由一个 Node 服务提供静态界面和健康检查。API 路径不被单页应用回退路由吞掉，从不同工作目录启动时静态资源定位正确。
- **实际验证（2026-10-02）：**Node 24.15.0、pnpm 11.1.0；`pnpm check`、`pnpm build`、`pnpm test` 通过。独立启动 `pnpm dev` 后验证首页与代理健康检查，再停止整组进程；生产服务从临时工作目录启动，检查 JS、SPA 路由、API 404 与缺失资源 404。`pnpm test:browser` 的开发/生产成功及失败状态共 4 项通过，并已查看成功、失败截图。界面仅为检查页，未迁移原型。

### [x] M1.2 验证 SQLite 与 PTY 原生依赖

- **验收：**在独立目录创建数据库、写入、关闭并重新读取；创建 PTY、执行无副作用测试命令、收到输出和退出状态，关闭后无测试进程残留。记录实际测试平台，不推定其他平台可用。
- **实际验证（2026-10-02）：**macOS 26.6.2 arm64、Node 24.15.0、better-sqlite3 13.0.3、node-pty 1.1.0。`pnpm test:native` 4 项通过（复开读取精确值、环境白名单、PTY 输入输出及退出码 7、强制关闭及 PID 消失）；`pnpm check/build/test` 与 frozen-lockfile 安装后复测通过。所有数据使用临时目录并删除。发现并解决 macOS prebuild helper 无执行位问题：提交 pnpm 包补丁以自动源码构建，使用现有 Python 3.14.6、CLT/clang 21.0.0，无工具链安装、无手工 chmod；条件详见 README。其他平台未验证。

### [x] M1.3 验证 Pi 与模型接入

- **交付：**固定同一版本的 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai`，验证初始化、响应流、工具调用、取消和失败事件。模型与凭据由服务端配置。
- **验收：**确定性测试能覆盖正常回复、一次工具调用、错误与取消；至少一个实际配置的 Provider 完成真实响应流验证。没有凭据时明确记录阻塞，不把模拟调用写成真实模型验证通过。
- **确定性验证（2026-10-02）：**Pi 两包均固定 1.0.0；测试覆盖流式文字、一次工具调用、Provider 错误、取消/并发拒绝，以及发送前的真实适配器参数检查；另有私有配置读取测试。`pnpm check`、`pnpm build`、`pnpm test` 通过（11 项服务端测试 + 1 项生产启动测试）。`.env` 只在服务端解析到私有对象，不写入 `process.env`；`.env.example` 保留空密钥。

### [x] M1.4 建立本地访问保护与配置边界

- **验收：**不同回答能进入正确的需求字段；草稿更新后仍可编辑；未确认不能作为正式需求启动路线规划；非法产物不覆盖已有有效草稿，失败后可继续对话或重试。

### [ ] M4.3 接入路线生成与调整场景

- **交付：**使用 `roadmap` 场景读取已确认需求和已有路线，生成结构化路线或变更提案；保存待确认产物并提供确认入口。
- **验收：**场景使用当前空间的需求和学习记录；未确认的提案不改变路线；重复确认只生效一次；基于旧路线的失效提案不能覆盖新状态，调整后已存在的学习记录不会被静默清空。

### [ ] M4.4 接入课程辅导与课件生成

- **交付：**使用 `tutor` 场景装配当前单元、必要学习结论和用户引用；课件生成作为独立任务，支持成功、失败和重试。学习结论与聊天历史分别保存。
- **验收：**引用课件、文件或终端输出后使用对应上下文；换单元后不误读上一单元；新 session 不虚构聊天记忆；生成失败不损坏已有课件或路线。来自文件和输出的内容不能改变宿主权限规则。

### [ ] M4.5 接入出题、评估与测评记录

- **交付：**为出题和评估定义任务输入、输出及记录；保留解释题、代码题、判断依据、加强建议、尚未验证项、重测和历史入口。评估输入包含实际执行结果时，区分运行失败与模型评估失败。
- **验收：**测评期间的辅导遵循引导而非直接给答案的原型约束；评估失败不写入虚假通过记录；作答、结果和尝试次数归属正确。此阶段使用明确标注的执行夹具验证协议，真实代码测评完成状态必须等待 M5.4。

### [ ] M4.6 验证场景权限与异常路径

- **交付：**建立确定性的场景、工具及非法产物测试，并进行真实 Provider 主流程联调；记录所用模型配置和可复现的失败条件，不记录密钥。
- **验收：**模型请求失败、响应中断、产物格式错误、重复重试和跨场景工具请求均被正确处理；不存在未经确认的路线变更。文件修改和命令执行工具在 M5.3 完成前不可执行。

**完成标志：**需求、路线、课程的非执行流程已接通真实模型；执行相关能力仍明确标为待 M5 集成，不能提前宣称完整测评已通过验收。

## M5：本机终端、操作确认与真实测评

**目标：**编辑器、Agent 和测评使用真实项目与执行结果，同时明确本机权限而非沙箱。

### [ ] M5.1 实现 PTY 生命周期与终端连接

- **交付：**在空间项目目录创建真实终端，接入受保护的浏览器连接、尺寸调整、输入输出和进程退出；终端环境不直接复制服务端模型凭据。
- **验收：**真实命令输出和退出状态可见；正常打开 IDE 自动建立或恢复终端连接，异常时才提示重连；关闭连接和关闭服务的行为区分明确，服务退出后不遗留应用拥有的终端进程。拒绝未经授权的连接。

### [ ] M5.2 接入终端界面与文件一致性

- **交付：**用真实终端替换模拟运行器，保持普通／全屏布局和输出引用。明确编辑器未保存内容与磁盘内容的区别，命令运行前给出必要的保存提示或完成保存。
- **验收：**修改并保存后执行的是最新代码；保存失败不能伪装成已经运行新版本；终端产生或修改的文件可以被项目树和编辑器发现；缺少工具链时显示真实错误与指引，不自动安装。

### [ ] M5.3 接通 Agent 文件和命令提案的确认执行

- **交付：**Agent 修改文件或执行命令先形成可查看的提案，展示目标路径、变更内容或命令及工作目录；用户确认后才执行。拒绝或过期不产生副作用，结果回到原会话。
- **验收：**未确认、拒绝和重复确认均不会额外执行；确认时文件已变化则提示冲突；执行内容与用户看到的提案一致；失败结果准确返回，取消不被描述为回滚。完成这些检查后才启用对应 Agent 工具。

### [ ] M5.4 接通真实代码测评并验证执行边界

- **交付：**用真实本机执行替换 M4.5 的执行夹具，固定被提交代码与输出的对应关系；执行入口明确告知将在本机运行，提供超时、输出限制、取消和清理处理。
- **验收：**正确代码、编译或运行失败、错误输出、超时和取消分别产生准确状态；超时或工具链缺失不能伪装成能力测评结论；测评期间编辑的新代码不会与旧执行结果混用。完成真实测评和重测全流程，并验证本机权限提示不宣称存在沙箱隔离。

**完成标志：**项目文件、终端与代码测评使用真实执行结果，Agent 的有副作用操作有明确的用户确认。

## M6：整体交付与使用文档

**目标：**用户能够在已验证平台上按文档启动应用，完整走通原型主流程，并在中断后继续。

### [ ] M6.1 验收完整学习主流程

- **交付：**建立浏览器端到端验收场景，串联需求、路线、学习、提问、项目文件、本机执行、测评和继续学习。
- **验收：**至少覆盖首次使用、路线调整确认、测评需加强后重测、两个空间切换、同一课程不同 session，以及查看历史测评后返回其所属单元。真实 Provider 和真实执行结果分别留有验证记录。

### [ ] M6.2 清理正式路径中的模拟逻辑

- **交付：**移除正式入口中的原型控制、硬编码教学回复和模拟环境状态；必要夹具仅留在测试或显式开发场景中。
- **验收：**生产构建不显示原型控制台，不用模拟数据填补模型或环境失败；未配置模型、无网络和缺工具链时展示准确状态。保留有用测试，不通过删除失败检查制造通过结果。

### [ ] M6.3 验证生产启动并补齐使用说明

- **交付：**提供安装、模型配置、开发、构建、生产启动、数据目录、停止服务和常见故障说明；注明 Node 及原生依赖要求、本机执行风险和已验证平台。
- **验收：**在干净配置与独立数据目录中按文档走通启动；生产模式只需一个本地服务且正确提供静态资源、API 和终端；端口占用、无效配置和数据库打开失败有可操作提示。不触发包发布或部署。

### [ ] M6.4 验证恢复、备份与最终回归

- **交付：**验证刷新、断线和进程重启恢复，提供停止服务后备份与恢复数据目录的步骤；整理最终测试和视觉检查结果。
- **验收：**测试数据备份恢复后记录与项目对应；升级程序不覆盖用户数据；中断运行不会自动执行历史命令；本地访问保护、路径边界和进程清理检查通过。对未验证平台及尚未通过的项目明确标注，不声称完整交付。

**完成标志：**已验证平台上的正式构建可以按文档使用；测试证据、已知限制和实际交付状态清晰。各节点已按实施纪律完成本地提交；推送、合并或发布的状态另行记录，不由本里程碑自动授权。

## 完成后再讨论的产品增强

以下内容不属于当前 27 项任务，不因出现在此前讨论中就自动实施：

- 将测评不足转成可追踪的补救任务，并用新情境再次验证。
