## 1. 原则：简单有效，每个约束都要有实际用途

模型负责表达业务内容，宿主负责内部 ID、资料关联、修订号、事务和存储。内容要求主要通过工具说明与提示词引导，不用固定清单、来源 ID、逐字符摘录或排版检查代替内容判断。

- 只向模型提供完成业务必需的参数，不直接把内部存储对象当作工具输入。
- 可以省略的说明、数组和辅助字段应真正可选，由宿主补默认值；同时检查实际发给模型的 JSON schema。
- 可无损处理的空白、标题标记等展示差异，在宿主处理，不要求模型反复重写有用内容。不能通过规范化悄悄删除正文或改变代码。
- 有真实消费者的结构保留，例如代码块的文件名和语言用于带入 IDE，评分中的不同反馈项用于学习结果展示。
- 保留空间归属、现有对象身份、版本冲突、用户确认、私有评分标准、真实执行证据、取消、事务回滚及公共网络保护。这些不是应删除的内容约束。
- 代码测评的预期输出比对具有业务意义，不等同于资料整理中的逐字摘录要求，不在本方案中放宽。
- 不新增工具注册平台、通用错误分类平台、配置体系或多 Agent 编排；在现有契约和业务所属模块中修改。

本次排查确认的是代码中的设计负担和失败条件，没有测量各问题对真实模型失败率的贡献。各待办中的验收描述是目标；已执行的检查单独记录在第 6～9 节。

## 2. 三个大修

### 大修 1：课件提交不应由排版细节决定成败

**涉及：** `submit_lesson`；[任务工具](../apps/server/src/agents/tasks.ts)、[课件契约](../packages/contracts/src/workspace.ts)、[课件提示词](../apps/server/src/agents/prompts/lesson.xml)。

**状态：** 已按用户批准的 Markdown 方案本地实现；新提交采用 `title` + `content`，旧课件只读兼容，不迁移重写。

**改造前的问题：**

- 新课件输入提供 `h2`、`p`、`markdown`、`list`、`code`、`callout`、`practice` 七种内容块，部分只是不同的排版表达。
- 目录 ID 由模型填写，重复 ID 会拒绝整个课件。
- `h2.text` 含 `##` 或任何换行都会被拒绝，包括仅在标题末尾多一个换行的情况。

**改造方向：**

- 收敛新提交的内容表达，正文优先使用 Markdown，避免强迫模型按段落、列表和提示框逐项拆分。
- 目录和锚点 ID 由宿主生成并处理重名；模型不管理内部目录身份。
- 保留服务于 IDE 的原始代码、文件名和语言信息，不把有业务用途的代码结构一并删除。
- 对标题标记和末尾空白做无损处理；标题混入多段正文时不能只取第一行而丢掉余文。
- 保持已保存课件可读，不为简化新输入而改写历史课件。只校验基本结构及确有消费者需要的字段。

**验收：** 普通标题、带 `##` 的标题和末尾换行的标题都能完整展示；相同章节名获得可用的不同锚点；正文没有丢失；代码缩进、复制和带入 IDE 的内容不变；历史课件仍可查看。取消、截断和失败提交仍不能覆盖已发布课件。

### 大修 2：首次路线规划一次表达完整安排

**涉及：** `submit_route`、`add_route_stage`、`update_route_stage`、`remove_route_stage`、`add_route_unit`、`update_route_unit`、`remove_route_unit`、`submit_route_proposal`；[路线工具](../apps/server/src/agents/route-tools.ts)、[场景工厂](../apps/server/src/agents/scenarios.ts)、[路线提示词](../apps/server/src/agents/prompts/roadmap.xml)。

**状态：** 已按用户批准的方案本地实现并提交。首次只装配 `submit_route`，已有路线保留七个编辑／提交工具；小修 8 一并完成。契约与验收见第 7 节。

**改造前的问题：** 首次规划也使用逐对象编辑接口。阶段数加单元数再加最终提交，就是最少工具调用次数；模型必须从工具回执复制阶段 ID 再添加单元。这些是内部构建工作，不是学习安排本身。工具调用次数不等于模型请求次数，但两者都存在额外组织负担。

**改造方向：**

- 首次创建支持一次提交完整的阶段、单元和安排说明，输入不含阶段／单元 ID，宿主统一生成。
- 已有路线的调整仍定位已有 ID，保留单元、课件、测评和学习记录的身份；不强行把编辑接口也改成无 ID 的整表覆盖。
- 沿用首次规划在需求确认后发布、后续调整由用户确认的规则。同步更新场景装配、提示词和回执，不让模型同时面对重复的首次创建流程。
- 同模块的无实际变化更新见小修 8，已在本项中一起完成。

**验收：** 一次无 ID 提交可创建多阶段、多单元的完整路线，顺序正确、宿主 ID 唯一；调整已有单元后历史记录和身份不变；真实内容修改后仍需重新提交；取消、失败及版本冲突不发布半份路线。

### 大修 3：不再用最后一次工具调用的输赢判定整轮成果

**涉及：** [运行层](../apps/server/src/agents/runtime.ts) 的工具错误门禁、[路线工具](../apps/server/src/agents/route-tools.ts)的暂存替换，以及各场景既有的 `commit()`。

**状态：** 已按用户批准的 Pi 风格错误反馈规则本地实现并提交；范围与验收见第 8 节，后续交付见第 10 节。

**改造前的问题：** 每次工具结束都会把 `toolFailed` 覆盖为当前调用的错误状态，运行结束时据此拒绝提交。有效草稿或文档之后发生一次可选抓取失败会阻止发布，反过来一次无关工具成功又能清除失败。业务结果不应依赖这种调用顺序。

**最终改造规则：**

- 工具错误继续返回给模型用于纠正，并保留在执行记录中；不把单个工具错误直接等同于整轮没有有效成果。
- 由产物所属场景判断最终提交是否有效、哪些产物必须存在；允许可选检索失败与有效成果并存。
- 保留本轮最后一次成功暂存的内容；之后失败的替换尝试不清空、不覆盖它，也不能被描述成已完成的新修改。这替代原先“最后一次提交尝试必须成功”的额外门禁，不增加提交状态协议。
- 已有路线的实际编辑仍使其提交失效，修改后的草稿必须重新完整提交；必需产物从未成功提交时仍不能发布。无关工具成功不能补造这些成果。
- 保留模型正常结束、取消、截断、归属、版本和事务检查，不将修改变为“无论发生什么都保存”。事实缺口仍由 agent 判断并说明，必要时继续提问。

**验收：** 有效产物加可选抓取失败，无论先后顺序均有一致的发布结果；失败替换保留同轮最后成功暂存，纠正提交才更新它；本轮没有有效必需产物或路线真实编辑未重新提交时不能发布；取消、截断、迟到结果和事务失败仍不留下半成品。覆盖 intake、路线、课件、出题、评分和辅导各自的产物要求。

## 5. 实施顺序、验证与交付边界

1. 原建议先处理大修 3；用户随后选择先实施大修 1、2。大修 3 现已采用 Pi 的错误反馈规则本地实施：移除末次工具门禁，保留成功暂存与场景发布检查，不增加通用错误分类或复杂状态机。
2. 大修 1 与大修 2 已分别本地实施并提交，保持历史课件、单元身份和用户确认契约。小修 8 随大修 2 完成并提交。
3. 用户决定小修 1 不处理；小修 2、3、9 一起修正输入 schema、宿主默认值和前端消费者，小修 4～7 在现有只读模块内完成。实施与验证见第 9 节。
4. 每项从上述业务反例验证结果，再执行相关类型、单元和场景回归。有 UI 展示变化时实际渲染并检查截图；不通过放宽断言或删除失败用例制造全绿。

测试优先使用确定性模型响应和可丢弃数据，覆盖字段省略、排版差异、调用顺序、分页停滞、Unicode 边界及历史身份。接口验收通过不证明真实模型的内容质量或失败率已改善；这部分需另做少量真实模型验证并如实记录结果。

已知普通浏览器的两项路线 textarea 可见性断言失败见 [intake 历史记录](./intake-design.md#7-本地实施与验证记录)，不是本清单中的工具问题，不能计为通过，也不借本轮工具简化修改无关产品行为。

第 6～9 节记录分阶段的本地实现和验证，小修 1 按用户决定保持现状。后续提交及试用服务切换准备见第 10 节；实际数据迁移、重启、合并或推送尚未执行。

## 6. `submit_lesson` Markdown 实施记录（2026-10-09）

### 6.1 最终输入与教学内容

工具只接受两个字段：

```json
{ "title": "课件标题", "content": "完整 Markdown 正文" }
```

- 不再要求 `intro`、块类型、章节 ID 或固定教学清单。导读、解释、表格、预期现象和适用边界写入正文。
- 正文保持原样存储，不裁剪首尾空白，不验证 Markdown 排版或增强块是否齐全；只检查类型、非空和已有容量边界（正文最多 100,000 字符，标题最多 200 字符）。
- 目录从顶层 `##` 标题生成，不把代码中的标题符号或折叠讲解中的标题当作目录。宿主生成重名标题的不同锚点，主课件与抽屉使用不同锚点前缀。

| 可选增强 | 写法 | 学习者行为 |
| --- | --- | --- |
| 代码示例 | 普通代码围栏；语言后可附 `file=demo.py`，带空格的文件名可加引号 | 语法高亮、复制原始代码、带入 IDE 的未保存缓冲区；不自动保存或执行。文件名省略时宿主提供默认名。 |
| 提示／警告 | 引用块首行 `> [!TIP]` 或 `> [!WARNING]` | 显示有标题和图标的提示框，其余内容仍用普通 Markdown。 |
| 动手练习 | `::::practice` / `::::`；内含可选 `:::hint` / `:::` 与 `:::solution` / `:::` | 直接显示问题，提示和参考讲解默认分别折叠；可独立展开。 |

```markdown
::::practice
先预测示例结果，再修改代码并解释原因。

:::hint
从本节概念出发，先观察变量变化。
:::

:::solution
给出参考思路、原因和适用边界。
:::
::::
```
