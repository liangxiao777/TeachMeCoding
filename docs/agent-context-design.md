# 教学 Agent 架构与上下文工程设计

- 日期：2026-10-03
- 状态：用户已确认本设计的关键决策，并批准新线程实施 M4；本文是实施约束，不是已完成能力或验证报告。
- 范围：M4 Agent 运行层、前置提问、路线、课程辅导及独立生成任务；不提前实施 M5 本机执行。
- 前置成果：本地 `main` 已包含 M1–M3 和原组件迁移修正。新线程必须从该本地基线创建语义分支，不以远端或云端默认分支替代。
- 关联：[总体实施计划](./implementation-plan.md)、[实施 ROADMAP](./ROADMAP.md)、[设计讨论](https://ampcode.com/threads/T-01a0fab8-e6f1-71e8-934b-d7d421fca500)。本文补充并更新旧计划中的 Agent 上下文、读取权限和会话记录约定；不改变浏览器文件编辑 API 的项目边界。

## 1. 目标与已确认决策

目标是让现有教学界面使用真实模型，在每次模型请求时提供当前任务需要的、来源和版本明确的信息；业务记录仍由应用校验和提交。提示词与上下文按代码管理，能够审查、测试和追踪变化。

| 事项 | 已确认方案 |
| --- | --- |
| Agent 框架 | 固定同版本 `@earendil-works/pi-agent-core`、`@earendil-works/pi-ai` 1.0.0；第一方场景模块，不建设插件平台 |
| 上下文格式 | 应用控制的指令和上下文使用独立、版本化 XML 资源及类型化编译；不在 TypeScript 中包裹巨大的 Markdown 字符串 |
| Pi 协议 | 保留原生消息角色、内容块、工具调用与结果结构，不将消息历史、工具参数和业务产物全部转换为 XML |
| 跨会话记忆 | 仅当前学习空间内共享已确认事实、有效测评记录和用户采纳的学习结论；不自动继承其他 session 原始聊天或未经确认的推断 |
| 文件读取 | Agent 自行读取相关文件，不要求用户逐次授权，不设置敏感文件名过滤或项目目录围栏，沿用 Pi 只读工具的宽松语义 |
| 默认目录 | 当前空间的受管项目目录是默认 cwd，不是沙箱；绝对路径、父目录、home 路径和符号链接目标按服务账号的 OS 权限访问 |
| 副作用 | M4 只读文件；不提供写入、编辑、bash 或命令执行工具。M5 的确认执行约定保持不变 |
| 留存 | 默认保留必要业务/会话记录及每次模型请求的上下文选择清单，不额外永久保存完整请求和自动读取的源码全文；完整调试快照需显式开启 |
| 模型 | 用户于 2026-10-03 确认从 DeepSeek 切换到 OpenRouter `stealth/space-bunny-alpha`，保留 `high` 推理；密钥只在服务端私有配置中，不擅自换用其他模型或暴露凭据 |
| UI | 正式入口继续使用原 `AppShell`、组件树与 `AppModel` 数据接口，不另写教学界面，不通过重录快照掩盖回归 |

上述文件权限意味着 Agent 可以读到服务账号可访问的凭据文件，并可能把内容发送给 Provider。XML 和提示词不能消除这项风险，也不能作为权限隔离。空间归属限制的是应用自动选择的业务上下文，不代表文件系统隔离。服务配置不得主动注入上下文、浏览器响应或日志；该要求与用户明确选择的自主文件读取能力须分别表述。

## 2. Pi 已有机制与应用需要补齐的职责

已对固定版本源码核实，并在规划阶段经 Oracle 架构审阅：

- `pi-agent-core` 管理内存中的 `AgentMessage[]`、模型/工具循环和事件，不负责持久化会话，不自带文件工具或权限模式。`sessionId` 是 Provider 相关元数据，不能替代产品会话。
- JSONL v3 会话树、分支、压缩记录属于 `pi-coding-agent` 的 `SessionManager`，不是 core 的隐含能力。它可通过 coding-agent SDK 使用，但需要额外依赖；当前不为存储引入整套编码 Agent 宿主。
- 继续以现有 SQLite 为业务持久化来源，服务端内部记录原生消息 JSON 及格式版本、运行和事件关系。保留可留存内容的原生结构；省略的工具正文用明确的留存标记表示，不伪装成完整历史。浏览器仍使用产品消息与事件协议，不暴露整个 Pi 状态。
- 不另建与数据库双写的 JSONL 主存储，不重造 Pi 的分支/压缩系统；将来需要导出或复用 `SessionManager` 时另行设计。
- 每次模型请求都会经过上下文准备/转换、消息转换和流调用；投影结果不会自动成为持久化历史。编译输入与投影均按不可变数据处理，不修改共享历史对象。
- `Agent.subscribe` 的异步处理会被等待，不能把未持久化的事件先宣布为已交付。`prompt()` 返回或 `agent_end` 仅说明循环结束，不能代替成功状态、产物校验和业务提交。
- core 不提供自动长期记忆、自动压缩或完整的总轮数限制。预算、停止条件与恢复由应用管理。

原生只读工具语义参考 coding-agent 的 `read`、`grep`、`find`、`ls`。实现时优先复用适配的公开 API，避免复制第三方 internals；如引入 coding-agent 包仅用于只读工具，须记录依赖理由，不连带启用它的会话宿主、扩展加载或完整编码工具。不得因复用工具而悄悄开放 bash/edit/write。

## 3. 四个服务端职责

```text
原有界面 / AppModel
        │ 提交、订阅、停止
        ▼
运行服务 ───────────▶ 业务模块 / SQLite
   │ 冻结输入               ▲ 校验与条件提交
   ▼                        │
上下文编译器 ──▶ Pi 适配器 ──┘
                     │
                     ├─ pi-agent-core + pi-ai → Provider
                     └─ 场景工具 → 业务查询 / 自主只读文件
```

| 责任 | 拥有的行为 | 不应承担的行为 |
| --- | --- | --- |
| 业务模块 | 空间归属、事实与修订、需求确认、路线提案、课件、结论、测评证据及事务 | 不接收模型直接 SQL；不在模型调用期间保持数据库事务 |
| 运行服务 | 请求幂等、session 活跃运行约束、独立任务、取消、有序事件、重连、恢复及最终提交 | 不拼接场景提示词；不把流结束直接当作业务成功 |
| 上下文编译器 | 类型化输入、场景选择、XML 编译、原生消息投影与来源清单 | 不设置上下文大小预算或按长度裁剪历史；不自行读“最新”数据库覆盖已冻结输入；不写业务记录 |
| Pi 适配器 | 模型配置、原生消息与工具装配、流调用、事件翻译 | 不拥有学习状态，不解析聊天措辞来更新业务 |

这些是逻辑边界，不要求每层都有框架、类层级或独立包。建议在已有 `apps/server/src/agents/` 内按实际职责组织 `runtime`、`context`、`prompts`、`scenarios`、`tools` 与独立任务模块；仅在代码需要时创建文件。`modules`、`storage` 继续拥有业务和存储；`packages/contracts` 仅增加前后端真正共享的 schema。

三个场景 `intake`、`roadmap`、`tutor` 通过明确的场景定义组合指令、上下文需求、工具和产物校验器。课件生成、出题和评估是独立任务，具有独立输入、预算和结果，不伪装成 tutor 会话，也不建设多 Agent 调度平台。

## 4. 一次运行及每次请求的契约

1. 接受用户请求：校验空间、session、单元和请求幂等键，持久化用户输入、必要引用及运行记录。相同请求重试返回同一运行，同一 session 不同时接受两个活跃运行。
2. 冻结本次运行必需的业务输入：需求、路线、单元、课件、测评题目等 ID 和修订版本；不只在模型返回时查询最新版本作为基线。
3. 组装当前请求：静态指令、类型化上下文、当前用户输入、同会话全部成功轮次及本轮工具链。上下文编译器保留消息顺序与完整内容，生成原生 Pi 请求投影和来源清单，不按大小拒绝请求或裁剪历史。
4. 调用 Provider，按有序事件持久化并分发消息流和工具进度。工具可读取本轮尚缺的信息；工具后的下一次模型请求同样生成独立清单，不做输入大小检查。
5. 校验产物 schema、来源归属、输入基线及目标当前版本，使用短事务和条件更新保存合法产物。首次路线由需求确认授权，成功后自动应用；已有路线的调整只保存提案，用户再次确认后才应用。
6. 记录明确终态。Provider 失败、输出截断、取消、重启中断、必需产物缺失、最终产物非法和基线失效不能伪装成成功；必要的部分文字可展示但标记未完成。

运行、生成任务、消息、结构化产物和业务完成状态须分别建模。独立任务按目标对象和版本防止重复提交；生成成功不自动等于用户已确认，也不等于单元已通过。

事件以运行 ID 和单调序号恢复；订阅游标恢复只能投递缺失部分，客户端按事件身份去重。切页/断线只断开订阅，主动停止才发出取消；服务重启将未完成工作标记为中断，不自动再次请求 Provider 或重放工具。取消与最终提交有明确先后判定：已完成提交不可被描述为撤回，先接受的取消不得随后写入成功产物。

M4 工具默认顺序执行。按后续产品要求，不设输入/输出 token、模型请求次数和工具调用次数上限，保留主动停止与每运行 300 秒超时。全部工具沿用 Pi 的错误反馈：参数拒绝、执行异常和显式错误结果进入模型上下文，由模型决定纠正、换方法或说明限制；不以末次工具错误否决整轮，也不以无关工具成功补造产物。成功暂存只有在新的提交成功后才被替换；各场景继续检查有效成果、基线与用户确认要求。执行记录保留每次调用的失败状态，整轮正常结束不将它改为成功。Provider 失败不自动重放收费请求。

首次路线用 `submit_route` 一次表达完整的阶段与单元，数组表达顺序和归属，宿主生成内部 ID。`summary`、`goals`、`note` 可省略，由宿主补空值；教学范围和学习目标通过说明引导，不用固定内容清单校验。当前场景只提供这个路线业务工具，共享检索等扩展能力保持原装配规则。

已有路线以小工具调整：添加/修改阶段和单元，移动或排序，撤销本轮误加的单元及空阶段。定位已有对象时复制当前路线或工具回执的 ID；禁止移除已有正式单元。更新中省略字段表示保留，新增单元的概要和目标可省略。`submit_route_proposal` 仅接收可选安排理由 `note`，验证当前组装结果；提交后的实际内容或顺序变化才使提交失效，无变化更新返回 `changed=false`。运行期间不发布部分路线，首次生成与后续调整的确认规则不变。

## 5. XML 资源与上下文编译

### 5.1 哪些内容用 XML

- 静态系统指令放在服务端独立 XML 资源：教学角色、当前场景职责、证据规则、产物和工具约束。
- 应用组装的动态业务上下文采用 XML 片段，包含作用域、版本、来源、任务数据和明确引用；作为原生消息中的数据内容传递，不提升为系统指令。
- 用户原始消息、原生 assistant/toolCall/toolResult 和 Pi 的 Provider 协议保持其原结构。工具参数和结构化产物仍使用 JSON/schema 校验。

示意资源如下，标签表达数据角色，不构成权限防护：

```xml
<context schemaVersion="1" scenario="tutor">
  <scope spaceId="…" unitId="…" sessionId="…" />
  <task kind="explain" />
  <confirmedFacts />
  <currentUnit revision="…" />
  <adoptedConclusions />
  <assessmentEvidence />
  <references />
</context>
```

可信指令与动态材料分离。用户输入、文件、终端输出、数据库自由文本或模型摘要即使含有 `<system>`、伪造工具指令等内容，也只能作为经过转义的数据；不把它们插入可信模板位置或变成新角色。模型仍可能受到提示注入影响，宿主必须独立执行工具集合、业务确认和产物校验规则。

### 5.2 把提示词当代码

- 提示词先说清任务，再说明何时提问、调用什么工具、交付什么结果。用直接、自然的句子；XML 只用于分段，不把数据库事务、版本校验等实现说明写成模型的工作步骤。
- 公共提示词只保留通用的交流、信息来源和工具结果规则；确认方式放在对应场景。首次路线随需求确认获得授权，调整已有路线才需确认提案，避免重复规则互相矛盾。
- 现有路线用 `summary` 说明学习内容及必要基础，用 `goals` 说明学完能做什么，用 `note` 解释安排原因；不为措辞问题新增前置能力字段或依赖图。
- 静态资源与 slot 输入类型、context schema、编译器版本和内容 hash 一起跟踪；slot 不允许注入任意未转义 XML。
- 使用可重复的序列化规则：固定段落顺序、明确空值、文本和属性转义、非法控制字符处理；禁用 DTD、外部实体及外部资源解析。
- 测试加载真实资源并解析编译结果，覆盖嵌套伪标签、`&`、引号、换行、非 ASCII 和控制字符，不仅比较漂亮的字符串快照。
- 系统指令装配保持唯一且确定，不让历史中残留的 system 消息抢占本次场景指令；不依赖 Pi 自动替换已有系统内容。
- 生产构建必须携带资源，且从非仓库 cwd 启动也能正确加载；不通过运行时读取源码目录补救丢失资产。

写作参考：[Codex 公开提示词](https://github.com/openai/codex/blob/58ca099b03029bcffd1c56b33d31bf4913c61cc1/codex-rs/core/gpt_5_codex_prompt.md)和 [Anthropic 提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)。参考清楚的动作、交付与授权边界，不照搬编码任务规则或假定其他模型的效果。真实模型检查使用自然学习需求，不在用户消息中提示工具名；与 XML/事务等确定性测试分开记录。

### 5.3 场景选择与会话隔离

| 场景/任务 | 默认必要输入 | 不自动加入 |
| --- | --- | --- |
| intake | 当前问题、需求草稿/确认状态、同 session 全部成功轮次 | 其他空间数据、其他 session 原文、无关代码 |
| roadmap | 已确认需求、当前路线及版本、相关有效测评和采纳结论、同 session 全部成功轮次 | 未确认需求当成事实、其他 session 原文、无关文件全文 |
| tutor | 当前单元与课件版本、当前问题/引用、相关事实/结论/证据、同 session 全部成功轮次 | 上一单元全部聊天、私有标准答案或 rubric |
| 课件生成 | 已确认目标、当前单元、相关资料/结论/证据，重新生成时的当前课件 | 完整路线与前序课件改为工具按需读取；不加入所有辅导聊天或随意变化的编辑器内容 |
| 出题 | 当前单元目标、课件版本、需验证的能力 | 无来源的掌握推断 |
| 评估 | 固定题目、私有 rubric、已提交答案及允许使用的执行证据 | 辅导时的友好猜测、可变草稿、与评分无关的学习者画像 |

先提供小而完整的默认上下文，其余按工具查询；首版不引入向量数据库。查询结果先经过应用空间/对象归属校验，再进入上下文。自主文件读取不受项目围栏限制，但不能因此把数据库跨空间记录默认灌入请求。

新 session 可使用上述共享事实，不能说“你刚才告诉我”来虚构同会话记忆。用户自述、辅导观察、已采纳结论、实际测评及真实执行证据必须有不同来源类型；自述熟悉某技术不等于测评通过。

### 5.4 单元顺序与按需读取课件（2026-10-10）

用户批准按单元锁定、路线完整可读、课件只向前读取的设计。路线包含阶段，阶段包含单元，每个单元对应一份完整课件；章节只是课件正文中的组织方式，不另建章节任务或上下文大纲表。

按阶段和单元的数组顺序展平路线。第一个单元可进入，其后的单元要求全部前序课件正式保存，不要求测评通过。已有后序课件不能越过前面的缺口，跳过状态也不能充当课件。浏览器展示锁定入口，直接链接返回路线；服务端在建立/重试生成任务、开始单元辅导和发布课件时校验访问顺序。工具成功暂存、Provider 失败或取消不会解锁。重新生成不删除已发布课件；失败后仍以旧课件是否存在计算解锁。解锁状态不持久化，不新增迁移。

课件业务工具遵循[工具设计原则](./tool-simplification-plan.md#1-原则简单有效每个约束都要有实际用途)：

| 工具 | 模型输入 | 返回给模型 |
| --- | --- | --- |
| `read_learning_route` | `{}` | 完整固定路线：`currentUnitId`、`note`、`stages[].title`、`stages[].units[]` 中的 `unitId/title/summary/goals/hasLesson`，包括后续计划 |
| `read_previous_lesson` | `{unitId}`，复制路线中前序单元的 ID | 一份固定版本课件的标题与完整 Markdown；无分页、摘要或字数截断 |
| `submit_lesson` | `{title, content}` | 成功暂存回执；正式保存仍等待模型正常结束及宿主提交校验 |

`hasLesson` 表示任务建立时已有正式课件，不表示掌握、解锁或允许读取该单元正文。前序课件工具拒绝当前单元、后序单元、不在固定路线中的单元及其他空间。模型不填写空间 ID、版本、页码或预算。

提示词自然引导生成前查看整体安排，再按需参考直接承接的前序内容，保持术语、示例设定与讲解深度连贯，避免重复或提前展开后续教学。没有读完全部课件、固定读取次数或章节清单门禁；已有课件也不是学习者掌握的证据。资料正文不是新的指令，发现技术错误时不机械延续。完整路线不重复塞进默认课件上下文，不预先拼接历史正文或自动生成摘要、依赖图、向量检索。

宿主在 `task_runs.input` 固定路线和已发布课件的版本引用；前序正文按需从现有 `lesson_versions` 查询，不回退到最新内容。只读兼容旧 `intro/blocks` 的全部文字与代码，不改写历史数据。来源/版本/hash 沿用每请求清单，工具正文沿用当前运行可用、持久消息省略的留存策略。

发布课件和重试前检查原需求、路线、当前课件以及所有前序课件版本，不只检查 Agent 实际读过的部分。来源变化或固定历史版本缺失时拒绝过期结果；原任务不会改用新版本，需新建生成任务。缺少版本引用的旧失败任务拒绝直接重试，明确的空引用快照仍允许首单元运行。不自动重生成后续课件，也不为历史课件补造来源关系。这是业务工具与访问流程边界，不是自主文件读取/Bash 的 OS 沙箱。

## 6. 运行限制、引用与文件读取

按用户后续明确要求，移除应用自设的输入和输出 token 预算，包括字节/token 估算、输入与输出预留相加的门槛、工具后二次输入检查、按大小省略历史、单次/累计输出上限及相关报错。生产模型保留真实能力元数据，模型本身的上下文窗口和输出限制由 Provider 决定；应用不另设上限，也不通过换算方式继续限制输入。

- 当前业务上下文、问题、引用、已提交测评答案、同会话成功轮次及本轮工具调用/结果均完整发送，保持原顺序和调用/结果配对；历史正文仍遵循独立的留存政策。
- 兼容性冒烟和生产传输都使用 Pi Provider-native `stream`，不走会估算上下文/输出预留的 `streamSimple`，实际请求不传 `max_tokens` 或 `max_completion_tokens`。累计 token 仅记录 usage，不参与终止判断。固定请求/工具次数限制一并移除以支持逐单元构建；超时、主动停止和 Provider 明确的 `length` 截断仍终止运行，不把不完整产物标成成功。
- 自主读取仍可分段、分页、限制单次返回体积并提示继续读取。这是独立的文件工具行为，不是输入上下文预算，也不是文件类型、路径或权限黑名单；不把浏览器编辑器的 1 MB UTF-8 限制套给 Agent 文件访问。

文件读取沿用字节游标：UTF-8 起点在字符内部时回退，末尾不拆字符，过小页长至少返回一个完整字符；范围、hash 与 `nextOffset` 均对应实际返回字节。含 NUL 的二进制页保持原字节范围与 base64。`grep` 的非空字面量可包含空格，支持单文件与目录，明确每文件仅扫描前 8192 字节。搜索普通分页返回推进的游标；扫描或深度上限则返回部分结果、`truncated=true` 和缩小路径提示，不让模型重复不能继续的偏移量。每次分页重新遍历，不增加游标存储，目录需在分页期间保持稳定。

引用记录必须区分用户贴入文字、课件片段、编辑器未保存缓冲、磁盘文件和终端输出，包含可用的对象 ID、版本/hash、范围与捕获内容。编辑器引用不冒充已写盘源码；粘贴内容不伪造来源。原有只含 `source/label/text` 的引用需兼容升级，旧引用保留为来源信息不足的数据。

文件快照指首次实际读取时的内容与版本，而非“运行开始时整个文件系统已冻结”。本轮若读取到变化后的版本，必须显式记录新版本或声明过期，不能把不同版本拼成一个快照。路径信息也属于敏感数据，清单仅留诊断所需信息，不额外写入普通日志。

## 7. 业务版本与证据提交

- **需求：**Agent 仅提交结构化草稿，按生成输入修订检查；迟到结果不能覆盖用户新编辑或确认。非法草稿不损坏原有有效值。
- **路线：**首次确认需求后进入原型的独立规划页，生成完整路线并通过输入版本校验后自动进入路线总览，不二次确认、不自动进入课程。确认需求与建立运行记录须原子提交，规划进度由真实事件恢复，不用计时器冒充完成。调整已有路线时才展示待确认提案；提案绑定生成开始时的需求和路线版本，确认时再次校验，不以返回时的最新版冒充输入版本。重复确认只生效一次，不清除既有学习记录。此区分按 2026-10-03 用户实测反馈恢复原型语义，取代此前笼统的“所有路线先确认提案”描述。
- **课件：**保存版本化、结构化内容，复用前端已有 `LessonBlock`、Reader 与目录能力；旧纯文本课件有兼容读取方案，不因新模型格式丢失旧数据。重试失败保留上一有效版本。
- **学习结论：**独立于聊天保存来源、作用域、采纳和有效状态；未采纳观察不自动成为长期记忆。摘要保留覆盖的来源和版本，来源撤销/失效后过滤或重建相关摘要，不能只删原记录而继续传播其结论。
- **测评：**题目公开部分与私有 rubric/答案分开。私有内容不进入公共 `UnitDetail`、浏览器消息或 tutor 可用业务工具；评估任务从服务端读取固定版本。
- **作答：**不可变的提交尝试与可编辑草稿分开，绑定题目、rubric、答案、代码和执行证据版本。迟到评估只更新对应尝试，不能读取或清空较新草稿。
- **结果：**区分模型评估失败、运行失败、未验证与有证据的结论。M4 可验证非执行题评分和结果协议，但执行夹具、缺失真实执行或模型臆测不得推进依赖代码执行的通过/掌握状态；完整代码测评等待 M5.4。

按 2026-10-09 的工具简化，解释题允许完整 Markdown，无起始代码默认 `""`，四组评分数组默认 `[]`；出题、评分声明采用输入 JSON schema，省略字段能真正通过 Pi 校验，解析后仍返回确定值。新代码题仅在工具提交入口要求执行方案，纯分析题和历史读取不新增要求；失败提交不替换已有成功暂存。私有 rubric、版本检查和代码通过的真实执行条件不放宽。提问工具按用户决定保持原契约。

“私有 rubric 不暴露”是产品 API 与自动上下文的职责，不应宣称 Agent 自主 OS 读取有数据库或文件级隔离；本产品已明确不提供这样的文件沙箱。不要把标准答案作为默认项目文件暴露给只读工具。

## 8. 会话、清单与留存

每次 Provider 请求记录独立清单，不仅每次用户运行记录一份。至少能回答：

- 属于哪个 run/session/任务、请求序号和场景；用了哪个提示词、context schema、编译器版本/hash。
- 实际模型、输出/推理配置、运行限制和 Provider 实际用量，不包含密钥，不再记录输入 token 估算或输入预算。
- 使用了哪些来源 ID、修订、hash、引用范围及同会话轮次；不再生成按大小省略历史的清单。
- 哪些工具内容仅在本轮内存存在，哪些按政策留存，哪些已省略；结果和终态对应哪个版本。

上述变化由上下文编译器版本区分；旧请求清单作为历史记录原样保留，不迁移或重写用户数据。

默认保存用户主动提交的消息、显式引用、模型可展示回复、合法业务产物、必要原生消息关系与请求选择清单。**自动读取的源码/toolResult 正文同样受留存策略约束**，不能因为放进 Pi 原生历史就绕过默认不永久复制全文的决策。

教学模型开启 `high` 推理。Pi 原生 thinking、签名和 redaction 标记保留在内部消息中供后续请求使用，不转成 XML，也不把签名发送给浏览器。可展示的推理、正文和工具状态通过已有事件表按请求/内容段/调用 ID 持久化，前端按顺序投影到 AI Elements；刷新、重连和停止使用同一事件投影。出题与评分会接触私有答案，因此仅公开推理阶段和工具状态，不公开模型推理及未经验证的回复正文。旧消息没有推理事件时仅展示原有文本，不伪造思考过程或耗时。

活动运行可持有完整工具结果。持久化时对不留存正文保留调用/结果身份和明确的省略标记；后续投影使用完整可用轮次，或显式标记历史结果不可用，不能产生孤立 toolResult。需要重新读取时产生新的工具调用及版本记录，不从当前磁盘伪造旧结果。

仅保存清单和 hash 不能承诺逐字重放历史请求。显式开启完整调试快照时须说明可能包含源码和隐私，将文件放入私有数据位置、不进入 Git、不在普通日志输出，并支持关闭和清理。仍不把服务端配置密钥对象作为调试输入。
