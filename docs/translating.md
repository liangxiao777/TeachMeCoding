# 界面翻译贡献

当前支持 English（`en`）和简体中文（`zh-CN`）。英文是规范源和运行时回退语言，资源随应用构建分发，不依赖在线翻译平台。翻译通过普通 Git 分支和 Pull Request 评审，不在运行时写回词典。

## 翻译的边界

翻译页面操作、导航、状态、空态、无障碍名称、第一方业务错误和日期／数字格式；异步失败、重新加载后的宿主回执、自动审批警告和执行摘要也属于界面文案。预览中的终端帮助／错误／退出提示、固定题型标题和宿主内置内存图标签同样进入词典。

不翻译用户输入和命名、Agent 生成内容、第三方 Provider／MCP／Skill 信息、程序 stdout／stderr、课程和学习记录中的原始反馈／证据。需求表中的问题和答案是可编辑的学习内容，不按文本猜测并翻译。宿主默认会话标题只保存空值，在显示时由 scope 和是否为该 scope 的首个会话生成，后续空标题显示「新会话」；任何非空标题都按保存的内容显示。引用保存 caption 的语义种类和原始名称，界面只翻译「课件／练习／选中代码／终端输出」等宿主标签，捕获的 label 和 text 不改写；没有 caption 的引用保留原始标签。回执只通过 receiptId 关联，不匹配消息文本。

语言优先级为当前浏览器保存的选择 → 浏览器语言列表中第一个支持的语言 → 英文。英语地区标签归为 `en`；`zh`、`zh-CN`、`zh-SG` 和明确的 `zh-Hans` 归为简体中文；不会把繁体偏好自动当成简体。设置页的语言选项使用语言自称。选择「跟随浏览器」清除显式偏好，其他选择仅保存在当前浏览器的 `tmc-language`，不写数据库、不改变教学模型语言、不刷新学习页面。

## 修改现有翻译

资源位于 `apps/web/src/i18n/locales/<locale>/<namespace>.json`：

- `common`：共享操作、文档元信息、通用控件及当前客户端提示。
- `home`、`settings`、`learning`、`workbench`、`assessment`、`library`：各功能页面。
- `errors`：第一方业务错误码的展示文案，不包含上游任意错误。
- `preview`：仅预览模式的宿主提示与固定示意图标签，不包含模拟课程／Agent 回复。

先找到页面使用的语义 key，再改对应 JSON。不要把英文句子当 key，也不要因为两处目前用词相同就合并语境不同的 key。修改功能或新增文案时，同一个 PR 更新英文和其他已支持语言；删除文案时同步删除不再使用的 key。

保留 `{{title}}` 等插值名，可根据语序调整位置。不要拼接完整句子的片段，不要翻译插值中的内容，也不要把凭据、异常堆栈或上游响应放进插值。数量使用 i18next 的 `count` 和本语言的复数形式，例如英文 `fileCount_one`／`fileCount_other`，中文只需 `fileCount_other`。数字、日期、相对时间使用已有 `Intl` 格式化函数，不在组件里固定地区格式。

React 组件用 `useTranslation`，纯展示函数用已初始化的 i18n 实例。当前错误／成功提示保留 `notice(namespace, key, values)` 或原始 `ApiError`，到渲染时才调用 `formatNotice`，不要在异步回调中把翻译后的字符串存入 state。这样切换语言时已有提示也会更新。

HTTP 错误只返回状态码、稳定业务 `code` 和允许公开的标量 `params`，不返回文案。新增业务错误时必须声明 code 并添加两个语言的文案。状态事件、运行／会话结果、模型配置的 issue、需求确认的 issues 和执行记录使用同一语义对象，不另设 errorDetail／issueDetail 等第二套字段，也不在前端提前压成字符串。未知码、无元数据的错误和原生网络异常显示当前语言的通用失败提示，不把任意 Error.message 当作界面文案；明确的第三方诊断与程序输出仍属于原始数据。不要把语言 key 放进数据库、Agent 工具输入或持久 SSE 事件；持久化的是业务语义，不是词典路径。宿主测评摘要只从 result 和 execution 派生；模型撰写的 needs_work 反馈保持原文。宿主回执只保存操作事实和关联，文件操作的宿主提示也不混入程序 output。

## 添加语言

从英文目录复制完整的 namespace 文件，翻译后提交；不要把未翻译的英文复制品当作已支持语言发布。在 `resources.ts` 注册资源，在 `locale.ts` 声明语言及明确的浏览器标签映射，再为设置页加语言自称。脚本／地区差异必须明确处理，不默认合并。当前界面按从左到右布局；新增 RTL 语言前需要另做布局和浏览器验收，不能只增加词典。

## PR 检查

```sh
pnpm check:i18n
pnpm check
pnpm --filter @teach-me-coding/web test
pnpm build
pnpm test:browser tests/browser/i18n.spec.ts --workers=1
```

`check:i18n` 检查与英文一致的 namespace／语义 key、非空字符串、插值一致性和本语言的复数类别，并用 TypeScript AST 批量检查第一方界面的直接文案、词典外中文，以及已移除的文案生成器、双字段和错误构造器是否被重新引入。品牌、语言自称、按键、编码等技术名称保持原文；命令参数示例显式使用 HTML 的 translate="no"。检查不判断翻译质量、不扫描课程／Agent 内容、不限制文案长度。TypeScript 使用英文资源推导 key 类型。轻量 GitHub Actions 检查词典与源码、前端类型和前端单元测试；不会在 CI 调用模型或外部翻译服务。

PR 说明受影响的页面、术语选择和例外，并附默认语言与新增／修改语言的实际页面截图。人工检查自然程度、术语一致性、按钮截断、换行、对话框、空态、错误态和窄屏；也要检查用户／Agent 原文没有被翻译。浏览器回归使用可丢弃数据和真实 PTY，模型场景使用确定性 Provider，不读写个人学习目录。中文浏览器回归显式固定 `zh-CN`；多语言用例自行指定 locale，不依赖开发者机器语言。

开发模式还运行标记词典检查：只替换浏览器内的英文资源，不添加生产调试开关，逐个打开设置页与对话框并检查可见文字和无障碍属性是否经过词典；主动插入未翻译按钮确认检查能够发现遗漏。生产构建使用正常词典验收。未知业务码、纯文本响应与原生网络失败均需验证只显示当前语言的通用提示。
